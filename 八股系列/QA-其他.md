# 其他类型

## 1. 开源框架了解过哪些？Qwen，Deepseek 的论文是否有研读过，说一下其中的创新点主要体现在哪？

**开源框架**

- **基础框架：** **PyTorch** 是目前大模型研究和开发的事实标准
- **模型与生态：** **Hugging Face Transformers** 是最重要的模型库和生态系统
- **大规模训练：** **DeepSpeed** (微软) 和 **Megatron-LM** (英伟达) 是进行大规模分布式训练的核心框架，实现了 3D 并行、ZeRO 等关键技术
- **高效推理：** **vLLM**, **TensorRT-LLM** 等框架专注于优化 LLM 推理速度和吞吐量

**Qwen 系列（Qwen2.5，Qwen3 系列）**

- **多模态统一：** Qwen-VL、Qwen-Audio 等统一架构处理图文音
- **长上下文扩展：** 支持 32K/128K+ 长文本
- **代码能力：** CodeQwen 专项优化

**Deepseek 系列（如 GRPO）**

- **GRPO（Group Relative Policy Optimization）：** 改进 RLHF，降低训练成本
- **MoE 架构优化：** 优化专家分配和负载均衡
- **推理能力：** 数学、代码推理专项优化

## 2. 最近读过哪些 LLM 比较前沿的论文，聊一下它的相关方法，针对什么问题，提出了什么方法，对比实验有哪些？

最近阅读了以下三篇 2025-2026 年的前沿研究，分别聚焦于推理增强、记忆架构和 Agent 系统：

---

**一、Search-R1: 强化学习驱动的搜索推理**

- **论文**: *Search-R1: Training LLMs to Reason with Autonomous Search* (2025年3月)

**针对问题：**

现有检索增强生成（RAG）存在两大瓶颈：

1. **静态检索局限**：传统 RAG 仅在推理开始前执行一次检索，无法在推理过程中根据中间结论动态探索新知识
2. **外部知识交互缺失**：长链条推理（Chain-of-Thought）无法实时验证或补充事实，导致多跳推理错误累积

**核心方法：**

基于 DeepSeek-R1 的 GRPO (Group Relative Policy Optimization) 框架，引入**自主搜索查询生成机制**：


| 组件          | 技术细节                                           |
| ----------- | ---------------------------------------------- |
| **训练范式**    | 端到端强化学习，不依赖过程监督，仅靠最终结果作为奖励信号                   |
| **动作空间扩展**  | 模型可生成 `<search>` 特殊 token 触发检索工具，实时获取外部知识并继续推理 |
| **推理-搜索交织** | 支持多轮迭代：生成推理步骤 → 自主决定搜索查询 → 获取新证据 → 修正推理方向      |


**关键实验对比：**

在 7 个问答数据集上的提升幅度：

- Qwen2.5-7B: 提升 +26%（基线 vs Search-R1）
- Qwen2.5-3B: 提升 +21%
- LLaMA3.2-3B: 提升 +10%

**优势场景**：HotpotQA 等多跳推理任务（需跨文档整合信息），显著优于标准 RAG 和 Self-Ask 方法。

**二、Engram: 条件记忆架构（DeepSeek-V4 核心）**

- **论文**: *Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models* (arXiv:2601.07372, 2026年1月)

**针对问题：**

Transformer 架构的根本性低效：

1. **计算同质化**：对"巴黎是法国首都"等简单事实和复杂数学推理使用同等昂贵的神经网络前向传播
2. **长上下文内存爆炸**：标准 KV 缓存在百万级 token 下呈二次方增长，导致 100K+ 上下文推理成本极高

**核心方法：**

提出 **Engram 模块** —— 在 MoE 架构旁新增**条件记忆层**，实现记忆与计算的解耦：

**1. O(1) 常数时间检索**

- **Multi-Head Hashing**: 将压缩上下文通过哈希映射到 DRAM 中的嵌入表
- **无需 GPU 计算**: 确定性知识检索完全在 CPU/内存层完成，仅当需要深度推理时才激活 GPU 计算层

**2. 上下文感知门控**

- **冲突抑制机制**: 当检索到的记忆与当前上下文冲突时，自动降低该记忆权重
- **稀疏分配定律**: 发现 20-25% 的稀疏参数应分配给记忆，其余分配给计算，达到帕累托最优

**3. 分层卸载架构**

- 可将 100B 参数卸载至 CPU/SSD，GPU 仅保留活跃专家（32B 参数），开销 <3%

**关键实验对比：**


| 基准测试                 | 改进幅度                | 说明                 |
| -------------------- | ------------------- | ------------------ |
| Needle-in-a-Haystack | 84.2% → 97% (+12.8) | 百万 token 上下文下的精准检索 |
| 知识密集型任务              | +3-5%               | 事实问答、常识推理          |
| 长上下文一致性              | 显著提升                | 支持 1M token 上下文窗口  |


**对比基线**：标准 Transformer、HippoRAG、传统 KV 缓存优化方案。

**三、Kimi K2.5 技术报告（Moonshot AI）**

- **报告**: *Kimi K2.5 Technical Report* (2026年1月27日发布)

**针对问题：**

1. **Agent 并行效率**: 单 Agent 串行执行多工具调用（1500+ 步骤）时延过高
2. **多模态训练冲突**: 传统后期融合视觉 token 导致视觉-语言表示不对齐
3. **长文本与推理的 Scaling**: 如何在 256K 上下文下保持强化学习的稳定性

**核心方法：**

**1. Agent Swarm + PARL（并行 Agent 强化学习）**

- **动态子 Agent 编排**: 主 Agent 将任务分解为可并行子任务，动态调度最多 100 个子智能体同时执行
- **PARL 训练机制**: 解决多智能体协同中的"串行塌陷"问题，通过奖励函数显式鼓励真正的并行执行
- **效率提升**: 相比单 Agent 串行执行，延迟降低 4.5 倍，支持单次运行 1500 次工具调用

**2. 原生多模态联合训练（Native Multimodality）**

- **早期低比例融合**: 预训练阶段采用 15 万亿视觉-文本混合 token
- **MoonViT-3D 编码器**: 原生分辨率视觉编码器，支持可变分辨率输入，通过轻量 3D ViT 压缩机制实现 4 倍更长视频处理
- **零视觉 SFT (Zero-Vision SFT)**: 发现仅使用高质量文本数据微调即可激活视觉推理能力

**3. 文本-视觉联合强化学习**

- **跨模态双向增强**: 在视觉任务上进行 RL，不仅提升视觉基准，还同步提升纯文本推理
- **Toggle 机制**: 通过高效的 RL 减少 25-30% 的 token 使用量而不损失准确率

**关键实验对比：**


| 基准测试                | Kimi K2.5  | 对比模型                                  |
| ------------------- | ---------- | ------------------------------------- |
| AIME 2025           | 96.1%      | GPT-5.2 (接近满分)                        |
| MMLU 2025           | 95.4%      | -                                     |
| SWE-Bench Verified  | 76.8%      | Claude Opus 4.5 (80.9%), Gemini 3 Pro |
| LLE-Full (w/ Tools) | 50.2%      | GPT-5.2 (45.5%)                       |
| BrowseComp          | 74.9-78.4% | GPT-5.2 (54.9%), Claude 4.5           |
| VideoMMMU           | 86.6%      | -                                     |


**架构规格**：

- 总参数：1.04 万亿（MoE）
- 激活参数：32B/Token
- 上下文窗口：256K tokens
- 视觉编码器：400M 参数 MoonViT-3D
- 开源协议：修改版 MIT（可商用）

**三项研究的技术关联与差异**


| 维度       | Search-R1       | Engram               | Kimi K2.5            |
| -------- | --------------- | -------------------- | -------------------- |
| **核心矛盾** | 推理时如何动态获取外部知识   | 推理时如何高效利用内部记忆        | 多 Agent 如何高效并行协作     |
| **核心策略** | 动作空间稀疏（仅在需要时搜索） | 参数使用稀疏（O(1) 记忆查找）    | 计算并行稀疏（100 Agent 并行） |
| **训练创新** | GRPO + 工具使用强化学习 | 稀疏轴与流形学习             | PARL 多 Agent 强化学习    |
| **延迟优化** | 多轮搜索增加延迟，换取准确性  | O(1) 查找降低记忆访问延迟 90%+ | 并行执行降低延迟 4.5 倍       |
| **适用场景** | 知识密集型问答、研究助手    | 长文档理解、代码库级编程         | 复杂工作流、多模态推理          |


**共性趋势**：三者均指向 **Test-Time Compute 的优化** —— 不再单纯扩大模型规模，而是通过机制创新（自主搜索、条件记忆、并行 Agent）在推理阶段动态分配计算资源。

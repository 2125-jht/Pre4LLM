> 核心目标: 将 RLVR（带可验证奖励的强化学习）从数学/代码领域扩展到**通用领域**，且**无需外部验证器**

---

## 一、背景与动机（为什么做这件事）

### 1.1 RLVR 是什么？

**RLVR** = Reinforcement Learning with Verifiable Rewards（带可验证奖励的强化学习）

- 近年来在提升 LLM 推理能力方面展现出巨大潜力（如 DeepSeek-R1、OpenAI o1 等）
- 核心范式: 通过领域特定的验证器（Verifier）为模型生成的回答打分，作为强化学习的奖励信号
- 常见验证器:
  - **数学领域**: Math-Verify 等符号验证器
  - **代码领域**: SandboxFusion 等沙箱执行环境

### 1.2 RLVR 的核心痛点

| 问题 | 说明 |
|------|------|
| **领域受限** | 现有 RLVR 几乎仅限于数学和代码两个领域 |
| **验证器成本高** | 手写规则验证器需要大量领域专家的人工设计 |
| **可扩展性差** | 每扩展到一个新领域，都需要重新设计和实现验证器 |
| **通用领域不可行** | 对于自由形式的自然语言答案，无法设计规则验证器 |
| **模型验证器复杂** | 训练专门的 LLM 作为验证器需要大量标注数据，且增加推理成本 |

### 1.3 核心洞察（Key Observation）

> **LLM 生成正确答案的内在概率，直接反映了它对推理质量的自我评估。**

也就是说：模型认为参考答案中每个 token 的概率高低，本身就是对推理过程好坏的自然度量——概率越高，说明模型越认可这条推理路径。

## 二、RLPR 核心方法（怎么做的）

### 2.1 整体框架

**RLPR** = Reinforcement Learning with reference Probability Reward

核心思想: **用 LLM 自身的 token 概率替代外部验证器的奖励**

```
传统 RLVR:  [问题] → [模型生成回答] → [外部验证器打分] → [奖励]
              ↑                                         ↓
              └──────────── 策略更新 ←──────────────────┘

RLPR:       [问题] → [模型生成回答] → [计算参考答案的token概率] → [奖励]
              ↑                                                     ↓
              └────────────────── 策略更新 ←────────────────────────┘
```

### 2.2 概率奖励计算（Probability Reward, PR）

#### 核心问题：为什么要用参考答案的概率？

**一句话回答**: RLPR 奖励的不是"模型对自己答案的信心"，而是"**在给定推理过程的情况下，标准答案有多合理**"。

| 做法 | 奖励的含义 | 问题 |
|------|----------|------|
| ❌ 直接用模型生成答案的概率 p(y\|z,Q) | "模型对自己输出的流畅度/信心" | 模型可能自信地说错话，奖励失去区分能力 |
| ✅ RLPR 用参考答案的概率 p(y*\|z,Q) | "推理过程 z 对标准答案 y* 的支持程度" | 客观评价推理质量，不受模型输出内容影响 |

**举例说明**:

模型回答同一道题，产生两个结果：
- o1: 推理正确 z1 → 答案正确 y1
- o2: 推理错误 z2 → 答案错误 y2

如果用 p(y\|z,Q)（模型对自己答案的信心）：
- o1: p(y1\|z1,Q) = 0.94（高）
- o2: p(y2\|z2,Q) = 0.93（也高！）→ 因为模型总是"自信地"输出自己采样出的内容

如果用 p(y*\|z,Q)（换参考答案后的概率）：
- o1: p(y*\|z1,Q) = 0.90（高，因为 z1 正确支持了 y*）
- o2: p(y*\|z2,Q) = 0.35（低！因为 z2 的推理与 y* 矛盾）

**所以必须替换为参考答案，才能客观评价推理过程的质量。**

#### 计算步骤:

1. **生成回答**: 给定问题 Q，策略模型 πθ 生成推理过程 z 和最终答案 y，即 o = z || y
2. **构造参考序列**: 保留推理 z，但将答案替换为标准答案 y*，得到 o' = z || y*
3. **前向传播**: 将 o' 输入模型，获取每个 token 位置的条件概率分布
4. **提取概率**: 对参考答案部分的每个 token y*_i，提取其在当前上下文（Q + z + y*_{<i}）下的概率 p_i
5. **聚合为奖励**: 

$$r = \frac{1}{|y^*|} \sum_{i \in y^*} p_i$$

即**参考答案所有 token 概率的均值**。

```
输入序列 o' = [z₁, z₂, ..., z_m,  y*₁, y*₂, ..., y*_k]
                ↑推理部分              ↑参考答案部分

位置 y*₁: p(y*₁ | Q, z)           → 取出概率 ★
位置 y*₂: p(y*₂ | Q, z, y*₁)      → 取出概率 ★
位置 y*_k: p(y*_k | Q, z, y*_{<k}) → 取出概率 ★

奖励 = mean(★, ★, ..., ★)
```

> **关键点**: 虽然答案换成了 y*，但概率计算时上下文**仍然包含推理过程 z**。所以奖励的是 "z 对 y* 的支持程度"。

#### 为什么用 mean 而不是 product（sequence likelihood）？

| 方法 | 公式 | 问题 |
|------|------|------|
| **Sequence Likelihood** | $r = \sqrt[n]{\prod p_i}$ | 对低概率 token 极其敏感。例如 (0.01, 0.7, 0.9) 和 (0.05, 0.7, 0.9) 乘积差异巨大，但实际语义差异很小 |
| **Mean Probability (RLPR)** | $r = \frac{1}{n}\sum p_i$ | 更鲁棒，对单个 token 的波动不敏感，与答案质量的相关性更好 |

> 注: VeriFree（同期工作）因为使用了 likelihood，不得不限制参考答案长度 ≤ 7 个 token，严重限制了数据多样性。

### 2.3 奖励去偏（Reward Debiasing）

#### 问题: 概率奖励受到哪些因素干扰？

概率奖励 r 本质上由两部分贡献:

$$U_r = U_z + U_{others}$$

- **Uz**: 推理过程 z 的贡献（我们真正想奖励的部分）
- **Uothers**: 问题 Q 和参考答案 y* 本身带来的偏差（需要消除）

#### 去偏方法:

1. 计算**基础分数** r'：直接让模型解码参考答案 y*（不加推理过程 z），计算其概率
2. 去偏后的奖励:

$$\hat{r} = \text{clip}(0, 1, r - r')$$

**直观理解**: r' 代表了"纯靠猜测参考答案"的得分，r - r' 才真正反映了推理过程带来的**概率提升**。clip 操作保证奖励在 [0, 1] 范围内。

### 2.4 标准差过滤（Standard Deviation Filtering）

#### 问题背景:

- 传统 RLVR 使用 **Accuracy Filtering**：过滤掉全对或全错的 prompt（太简单或太难）
- 但 RLPR 的奖励是连续值 [0, 1]，无法用 0/1 的正确性阈值

#### 核心洞察:

- **全高奖励**或**全低奖励**的 prompt → 标准差小 → 对训练贡献小
- 需要过滤掉这些 prompt

#### 动态阈值策略:

- 使用**指数移动平均（EMA）**动态更新过滤阈值 β
- 每步过滤掉奖励标准差 < β 的 prompt
- 自适应课程学习：随着训练进行，自动调整过滤严格程度

> 静态阈值的问题：训练初期和后期奖励分布差异大，固定阈值会过松或过严。

## 三、训练目标与算法

### 3.1 最终梯度估计

$$\nabla J_{RLPR}(\theta) = \mathbb{E}_{o \sim \pi_\theta(\cdot|x)} [\hat{r} \nabla \log \pi_\theta(o|x)]$$

其中 o = z || y 是完整回答（推理 + 答案）。

### 3.2 训练配置（关键超参）

| 参数 | 值 |
|------|-----|
| 基础模型 | Qwen2.5-7B / Llama3.1-8B / Gemma2-2B |
| 训练框架 | verl (HybridFlow) |
| 算法 | GRPO（默认） |
| Batch Size | 768 |
| 每 prompt 采样数 | 8 |
| 每步策略更新次数 | 4 |
| 温度（训练） | 1.0（Qwen）/ 0.6（Llama, Gemma）|
| Clip Threshold | (0.8, 1.27) — 防止熵坍缩 |
| 熵惩罚系数 | 1e-3 |
| KL 惩罚 | 0（不使用） |
| 学习率 | 5e-7（policy）/ 1e-6（部分实验）|
| 过滤阈值 β | 0.5（默认） |
| 最大生成长度 | 3072 |
| GPU | 32 × NVIDIA A100 |

### 3.3 训练 Prompt 模板

采用 DeepSeek-R1 的风格，要求模型输出 `<think>` 和 `<answer>` 标签：

```
System: ...The assistant first thinks about the reasoning process in the mind 
and then provides the user with the answer. The reasoning process and answer 
are enclosed within <think></think> and <answer></answer> tags...

User: {{question}}

Assistant: <think>...推理过程...</think> <answer>...最终答案...</answer>
```

## 五、奖励质量分析（深入理解 PR 的有效性）

### 5.1 ROC-AUC 评测

用人类标注作为 ground truth，评测不同奖励对"正确/错误回答"的区分能力:

| 奖励方法 | 数学数据 AUC | 通用数据 AUC |
|----------|-------------|-------------|
| Rule-based Verifier | 0.95 | **0.61**（很差）|
| General-Verifier（1.5B）| 0.92（下降）| 0.69 |
| **PR（RLPR）** | **0.97** | **0.81** |

**关键发现**:
- 规则验证器在数学上表现好（0.95），但在通用领域几乎失效（0.61）
- PR 在**两个领域都表现优异**，通用领域比规则验证器高 **20%**
- 即使是最小的 Qwen2.5-0.5B 模型产生的 PR，也超越了专门训练的 General-Verifier

### 5.2 PR 的鲁棒性

- **与长度无关**: Spearman 相关系数仅 -0.060（p > 0.05）
- **与熵无关**: Spearman 相关系数仅 0.059（p > 0.05）
- 说明 PR 不会偏袒长回答或短回答，也不会导致熵坍缩

## 六、消融实验（验证各组件的必要性）

### 6.1 消融结果（Qwen2.5-7B）

| 配置 | TheoremQA | Minerva |
|------|-----------|---------|
| **完整 RLPR** | **55.4** | **56.5** |
| w/o debiasing（不去偏）| 52.7 (-2.7) | 54.1 (-2.4) |
| w/o std-filtering（不过滤）| 52.5 (-2.9) | 55.1 (-1.4) |
| w/o token prob（用 likelihood）| 33.5 (-21.9) | 34.2 (-22.3) |

**结论**:
- **Token 概率均值** 是最关键的组件，去掉后性能暴跌 ~22 分
- **去偏** 和 **标准差过滤** 各贡献 2-3 分提升，都很重要

## 七、RLPR 在可验证领域（数学）的表现

### 7.1 与规则验证器的结合

即使数学领域已有完美的规则验证器，RLPR 仍能提升性能:

| 奖励方法 | TheoremQA | Minerva |
|----------|-----------|---------|
| Rule-based only | 44.8 | 48.8 |
| **Rule-based + PR** | **50.0** | **49.0** |

**原因**: 规则验证器只有 0/1 的粗糙信号，而 PR 能提供**细粒度的质量区分**（如 "199" 比 "1" 更接近 "200"）。

## 八、与相关工作的对比

### 8.1 对比总结表

| 方法 | 验证器需求 | 奖励类型 | 领域限制 | 关键局限 |
|------|-----------|----------|----------|----------|
| **RLVR (传统)** | 规则验证器 | 0/1 二值 | 数学/代码 | 无法扩展到通用领域 |
| **General Reasoner** | 1.5B 模型验证器 | 0/1 二值 | 通用 | 需训练验证器，复杂且成本高 |
| **VeriFree** | 无 | Likelihood | 通用（短答案≤7 token）| 长答案不稳定，需辅助 loss |
| **RLPR (本文)** | **无** | **Token 概率均值** | **通用（无限制）** | 无 |

### 8.2 与 Self-Reward 方法的区别

Self-Reward 方法（如 TTRL）: 提高一致性答案的概率，本质上是**熵最小化**
- 问题: 限制探索，可能导致多样性丧失

**RLPR**: 基于参考答案构建奖励，配合 clip-high trick 保持健康的 token 熵
- 优势: 推理性能提升 + 合理的生成多样性

## 九、面试高频问题与回答要点

### Q3: 为什么不用 sequence likelihood 而用 mean probability？

**答**: Likelihood 是概率的乘积，对低概率 token 极其敏感。例如 (0.01, 0.7, 0.9) 和 (0.05, 0.7, 0.9) 的语义差异很小，但 likelihood 差异可达 5 倍。Mean probability 更鲁棒，与答案质量的相关性更好（AUC 更高）。

### Q4: Reward Debiasing 的作用是什么？具体怎么做？

**答**: 原始概率奖励包含两部分: 推理过程的贡献 + 问题和参考答案本身的偏差。Debiasing 通过计算"不加推理直接猜答案"的基线分数 r'，用 r - r' 得到真正反映推理质量的去偏奖励。直观理解: 奖励的是"推理带来的概率提升"。

### Q5: Standard Deviation Filtering 的原理？为什么不用固定阈值？

**答**: 核心洞察: 全高或全低奖励的 prompt 标准差小，对训练贡献小。用 EMA 动态更新阈值 β，因为训练过程中奖励分布会漂移，固定阈值会过松或过严。

### Q7: 既然数学领域有完美验证器，RLPR 在数学上还有价值吗？

**答**: 有。规则验证器只有 0/1 信号，PR 提供细粒度质量区分。实验表明 Rule + PR 的组合优于纯 Rule（TheoremQA 44.8→50.0）。此外 RLPR 训练不需要验证器实现，部署更简单。

### Q8: RLPR 的训练稳定性如何保证？

**答**: 三个机制:
1. **Clip-high trick**: clip threshold (0.8, 1.27) 防止熵坍缩
2. **标准差过滤**: 动态过滤低方差样本
3. **去偏奖励**: 消除系统偏差，减少噪声

训练日志显示: response length 稳定增长、format reward 快速收敛、token entropy 健康不坍缩。

### Q9: 概率奖励和模型置信度有什么关系？

**答**: 概率奖励本质上是模型对参考答案的"置信度"。但不同于简单的模型置信度，RLPR 通过 (1) 只关注参考答案 token 的概率（而非整个序列），(2) 去偏处理，(3) 均值聚合而非乘积，使得这个信号更精确、更鲁棒。

### Q11: 这个工作的局限性是什么？

**答**:
- 需要参考答案（不能像 TTRL 那样完全无监督）
- 概率奖励有噪声（虽然通过去偏和过滤缓解了）
- 在长文本生成上的效果未充分验证
- 多模态领域的扩展是未来工作

## 十一、个人理解与延伸思考

### 为什么 RLPR 有效？本质洞察

RLPR 的成功验证了一个重要假设: **LLM 的内在概率分布本身就是一种强大的"自我评估"机制**。不需要外部裁判，模型自己就能判断"这条推理路径通向正确答案的可能性有多大"。

这与人类认知有相似之处: 当我们解完一道题，内心会有一个"信心度"——这个信心不是来自老师批改，而是来自解题过程中每一步的确定性感受。

### 可能的延伸方向

1. **与 Process Reward 结合**: 当前 PR 是 outcome-based，能否扩展到过程级别的概率奖励？
2. **多模态扩展**: 论文提到这是未来工作，视觉-语言任务的验证器更难设计，RLPR 的价值更大
3. **更大规模模型**: 论文只在 7B 级别实验， scaling 到 70B+ 的潜力
4. **完全去除参考答案**: 结合自一致性（self-consistency）或 majority voting，实现完全无监督

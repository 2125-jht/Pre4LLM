# 二、VR-CLIP（CVPR 2026 一作）

> CLIP在图像级任务上表现很强，但做像素级密集预测时有个本质问题：它的视觉特征是为图像-文本对齐优化的（对比学习），导致同一物体内部的特征不连贯，patch特征尤其离散。现有方法主要靠更强的decoder来弥补，但终究受限于输入特征的质量。
> 
> 一个思路是用微调视觉编码器，我们发现这会破坏CLIP的视觉-语言对齐能力，导致性能显著下降。所以问题的核心是：如何在保持视觉-语言对齐的前提下，提升像素级判别能力？
> 
> NSA：插在CLIP ViT的浅层 1-2 layers（非语义层），用深度可分离卷积+通道混合，聚合局部邻域信息，增强空间连续性。
> SGR：从对齐好的文本向量角度，基于相似度映射将类别级语义信息注入视觉特征，实现残差式层级语义校正，但对unseen类别无效，另外我们采用跨层MLP参数共享机制，学习共性映射，unseen急剧提升+5%。
> 在PASCAL VOC和COCO-Stuff上取得一致的提升。训练参数量只占8%。

---

1. 为什么 CLIP 做密集预测会有问题？微调为什么会破坏对齐？
> CLIP 预训练的目标是全局图文对齐，ViT 的全局注意力让同一物体内部的 patch 特征不连贯，特征过度集中在最具区分性的区域。
> 从语义的角度。视觉特征改变了，文本编码器却冻结着，两者原本共享的嵌入空间被拉开。更具体地说：Seen 类过拟合，视觉特征向训练域类别漂移，unseen 泛化能力直接崩盘。

1.  NSA 为什么放在浅层？它相比 self-attention 额外建模了什么？
> NSA 从不影响语义的角度出发捕捉浅层局部信息。浅层编码的是低级模式（边缘、纹理、颜色过渡），天然需要局部卷积聚合；深层关注全局语义，卷积帮助有限，且过度修改会破坏预训练表示。
> Self-Attention 建的是全局长程依赖，NSA 额外建模的是局部邻域空间关系。
> 
> 把 token 序列 reshape 回 2D 特征图，用多尺度 depthwise 卷积在邻域内做空间平滑，再经通道混合投影回去 —— 本质上是在 token 空间里显式引入了局部连续性先验。

2.  SGR 相似度分数怎么算？残差修正是什么？为什么用类别向量初始化 100 个的语义tokens？
> 把 CLIP 文本编码器输出的类别 embedding 投影到视觉空间，得到语义 tokens，再和当前层的视觉 patch 特征算 scaled dot-product，过 softmax。本质上就是像素-类别关联的注意力图。
> 残差连接是为了让语义修正始终是对原始 CLIP 特征的增量微调，而不是覆盖式重写。
> 
> 原始类别向量太粗了 CLIP 文本编码器输出的是类别级 embedding。但像素级分割需要的语义粒度远不止"这是猫"——它还要区分猫的边缘、纹理、部位关系、上下文共现等。用这么少的向量去做像素-语义关联，信息容量不够
>
> 这100个token是可学习的，但不是随机初始化。我们用类别 embedding 去初始化/约束它们，相当于给这些 token 一个先验：起点必须在 CLIP 已经建好的语义空间里，训练时不会跑偏到无关的随机方向。这样既保留了 CLIP 的对齐能力，又给了模型足够的自由度去学更细粒度的语义分解。
> 为什么是 100 个？我们试过 20、40、100、160：太少（20/40）：容量不够，表达不了 part-level 概念太多（160）：token 之间冗余交互，similarity map 变嘈杂，反而影响残差修正的稳定性 100 个是甜点：足够表达细粒度语义，又不至于引入噪声。

2.  跨层 MLP 参数共享？共享的动机是什么？共享后为什么更有利于 unseen 类别泛化？
> SGR 里有两个 MLP，一个做语义聚合，一个生成残差。共享是为了减少参数，同时强制所有层用同一套映射规则。独立参数会让每层学各自的语义映射，绑定到 seen 类的分布上，过拟合风险大；共享参数强制学习一个跨层统一、与具体类别无关的"共性映射"，新类别的语义 token 也能走同样的投影路径，泛化更稳。
> 
> 由于所有层共享同一个映射，这个映射在训练时被 12 个不同深度的特征监督，相当于获得了 12 倍的监督信号（虽然数据相同，但输入分布不同），学习到的映射更鲁棒、更通用同时，共享也起到了**隐式的正则化作用**。

3. 这个工作最大的 failure case 是什么？如果现在让你继续做这个方向，你下一步会怎么改进？
> 极端光照/低对比度场景： 昏暗环境下的类别，像素特征本身就很弱，语义修正信号容易被噪声淹没。
> 小目标：因为 ViT/16 的 patch 粒度本身就是瓶颈，方法层面没有专门处理。
> 倾向于在 encoder 内部把 SAM 的 patch 特征作为辅助引导信号（比如加到 NSA 里做混合局部聚合）。

# 三、零样本异常检测（under review 二作）

> 我们发现现有CLIP-based方法都在强化文本编码器，如prompt tuning等。但异常检测本质是视觉任务--判断"视觉模式是否偏离正常"。过度优化文本会导致语义过拟合，即文本特征过度适应训练域的语义表达，难以迁移到新场景。
> 比如"defect"在工业场景指划痕，在医疗场景指病变区域。文本微调让模型"记住"了特定域的语义，但异常检测需要跨域泛化。另外，很多异常（如不规则纹理、细微形变）难以用文字精确描述，但视觉特征可以直接捕捉。
> 
> 我们提出视觉主导的ZSAD范式，核心模块包括：VFM用多尺度卷积结构增强视觉特征感知，PFM实现渐进式多层级特征融合。TCM（Text Correction Module）：推理阶段利用测试图像自身的高置信度patch特征动态校正文本原型，实现自适应对齐。

---

1. 什么叫“渐进式融合”？
> 渐进式融合模块。它不是把每层特征独立拉出来做下游任务，而是逐层递进融合——当前层的 VFM 输出会和上一层融合后的特征做 Hadamard 乘积 + 拼接，再经 1×1 卷积降维，传给下一层。这样浅层的细粒度细节和深层的高级语义是逐步互补的，而不是最后才拼接

2. 文本校正机制？文本原型如何更新？
> 先用初始文本特征（正常 T_N、异常 T_A）和视觉 patch 特征算 cosine similarity，得到初始 anomaly map。从 anomaly map 里筛选高置信度 patch：正常 patch 选与 T_N 相似度最高的 top-k，异常 patch 选 anomaly score 最高的 top-k。
> 
> 分别平均这些 patch 的特征，得到视觉证据 V_N 和 V_A。加权更新文本原型：T̃_N = α · Average(V_N) + (1-α) · T_N，α 很小（0.02），文本特征只是被视觉证据"微调"，不是被替换。

# 四、通用推理增强（Post-training）

> 传统RLVR方法（如DeepSeek-R1）主要局限在数学和代码领域，因为它们依赖规则验证器——数学题可以验证答案对错，代码可以跑测试用例。但开放域的自然语言推理任务没有标准答案，无法设计通用验证器。我们想做的是**不依赖验证器的通用推理能力增强**。
> 问题的本质是：**如何为通用领域推理任务提供有效的奖励信号？** 现有方法要么需要人工标注推理过程（成本极高），要么只能处理特定领域（rubric）。我们需要一种能扩展到任意推理任务的奖励机制。
>
> 整体采用 冷启动SFT + RLPR两阶段 方案：
> 冷启动阶段：基于DeepSeek-R1范式，用Few-shot Prompting合成8K高质量CoT数据，让模型学会规范的推理格式。
> 
> RL阶段：核心思想是 概率奖励 —— 用模型对参考答案的解码概率作为奖励信号（hacking？），相当于奖励的是"这段推理对参考答案的支持程度"，即推理质量本身。
> 奖励去偏 ：因为有的题目天生难/易，把推理过程去掉，直接问模型"这个问题的答案是什么"的概率，减去无推理时的基线概率，消除题目本身难度偏差。
> 自适应标准差过滤 ：动态筛除太简单或太难的样本，解决奖励稀疏导致的训练不稳定。
> 
> 训练：基于GRPO算法，去除KL约束（KL_coef=0），提升clip_eps=0.27，提升探索空间。
> MMLU-Pro+4.2%、TheoremQA+10.1% 平均推理能力+7.5%，定理应用类推理上进步明显。

---

1.  为什么用 Qwen2.5-7B 做基座？为什么选择冷启动 SFT + RLPR 两阶段？为什么不用纯 SFT？
> 指令跟随能力稳定，SFT 阶段格式收敛快，降低了后续 RL 阶段因格式崩溃导致的不稳定风险。
> RL 训练需要模型先具备基本的推理格式能力，否则探索空间太大、收敛困难。
> SFT 本质是模仿学习，上限受限于训练数据的分布和质量，数据覆盖的推理模式有限，模型容易过拟合到训练数据的表面模式，且无法自主发现更优的推理路径（如自我反思、多路径验证）。

1.  8K CoT 从哪里来？数据类型包含哪些任务？
> 用 Few-shot Prompting + 教师模型蒸馏。具体来说，给 DeepSeek-R1 提供 3-shot 示例（格式要求），让它为种子问题生成完整的推理轨迹。这样保证输出格式统一、推理链质量高。
> 覆盖五类任务——数学推理 30%、科学推理 25%、逻辑推理 20%、代码推理 15%、人文社科 10%。

1.  77K 高质量 RL 样本，筛选时推理复杂度评分是怎么做的？为什么阈值设为 ≥3？
> 1-4分。1分模型靠预训练知识就能答对，RL 没有优化空间。2分太开放或太简单，奖励信号弱、区分度差。3分数据最多，需要多步推理、有确定答案，既能让模型学到推理模式，又不会因过难导致奖励稀疏。4 分题需要深度理解占比很低，7B 模型对过难题目的学习效果差，容易训崩。≥3 在"质量"和"数量"之间取得了平衡。

1.  10-gram 去重避免数据污染？去重对象是什么？
> RL数据来自公开数据集，极易与评测集存在重叠或改写，10-gram比短5-gram更严格，能捕捉到片段级重复，防止"换皮题"导致的数据污染。去重对象：题目，不需要对答案或 CoT 去重。

2.  概率奖励 相比于传统 RLVR 或基于 Reward Model 的优势？避免序列似然的高方差问题？
> RLVR 奖励信号没这个细致（0-1）；奖励模型容易遇到 reward hacking！（GRPO本身、奖励去偏）。
> 序列似然对低概率 token 极度敏感，奖励方差极大，需要限制答案长度 ≤7 token，我们突破了长度限制。

2.  奖励去偏 策略消除题目本身难度偏差，怎么解释？
> 模型对标准答案的解码概率天然受两个因素影响——推理质量（我们想要的）、题目本身难度（系统偏差）。
> 例如高数题的参考答案概率天然低于常识题，简单题的基线概率本来就高，这会导致奖励不可比。

2. 自适应标准差过滤 动态筛选样本，解决奖励稀疏导致的训练不稳定，怎么解释？
> 太简单（8个回答奖励都很高）或太难（都很低），这些样本梯度信号极弱，浪费计算甚至导致模型退化。
> 通过计算这8个奖励的标准差σ。训练初期模型能力弱，随着模型变强，标准差自然提高，阈值也相应上浮。

3. 关键的超参数有哪些？KL=0，为什么 KL 敢设成0？
> KL（防止策略偏离参考模型太远）、clip（重要性采样比率裁剪边界）、温度（系数越大多样性越好）控制采样多样性。
> 
> GRPO 的组内相对优势已经提供了足够的稳定性约束，同一 prompt 的 8 个回答做归一化（减均值除标准差），天然限制了极端更新，去掉 KL 后（clip约束仍在），模型获得了更大的探索空间。
> 虽然KL系数为 0，但仍进行监控。响应长度异常暴涨或格式奖励骤降，都是 policy 崩坏的早期信号。
> clip 系数过高：参考模型的 KL 快速上升、同一 prompt 的8个采样越来越像（组内标准差趋向 0）。

3.  如果继续优化这个项目，你更想从哪边入手：
> 从 结果-based 概率奖励 扩展到 process-level 概率奖励。

# 五、智能培训助手（RAG 问答系统）

> 这个项目是面向企业知识培训场景。企业有大量技术文档、产品手册、培训资料（200+份PDF），新员工需要快速学习。但PDF文档有多栏排版、密集表格等特点，传统检索方式效果很差。
> 文档处理：采用 "表格保护+规则边界" 切块策略，用PyMuPDF提取文本+pdfplumber解析表格（markdown），正则表达式确保表格不被切断，文本在句号/换行处切分。
> Query改写：指代消解（处理"它"、"那个"等代词指代）+ LLM Query改写（将模糊、不完整的查询转化为检索友好的表达）。
> 召回排序：BM25（BestMatch25 查询词在文档中出现的频率、文档长度、稀有程度来计算相关性）+Dense混合召回+RRF融合策略，Top20召回后用Cross-Encoder重排到Top5。
> 部署优化：vLLM + AWQ 4bit量化部署Qwen2.5-14B，单卡显存从28GB降到10GB。
> 自建60条三类型评测集（事实型/对比型/汇总型），混合召回Recall@5达到87%，较纯向量方案提升15pp。重排后准确率提升14pp。

# 六、快手 OneRec


看过 OneRec 吗？介绍一下
> OneRec 是快手提出的工业级统一生成式推荐系统，核心目标是用一个端到端生成模型重塑传统推荐里的多阶段级联链路，比如召回、粗排、精排、重排。传统推荐系统的问题在于链路很长，各阶段目标不完全一致，模型之间存在信息损耗和目标冲突，同时大量资源消耗在通信、存储和多阶段候选传递上，很难像大模型一样通过统一架构持续 scaling。OneRec 的思路是把推荐问题重新建模成生成问题：给定用户画像和历史行为序列，模型不再只依赖候选集逐个打分，而是自回归地生成用户可能感兴趣视频的语义 ID，再映射回真实视频。

> 整体架构上，OneRec 主要包括 Tokenizer、用户 Encoder、生成式 Decoder 和 Reward System 四部分。Tokenizer 负责把十亿级视频库中的视频压缩成粗到细的层次化语义 ID，而不是直接生成原始 video id。它利用视频的多模态内容，比如标题、ASR、OCR、封面、视频帧等，再结合协同信号，通过 RQ-Kmeans 生成 3 层 semantic id。这样相似视频会共享部分语义 token，新视频只要有内容特征也可以被编码，能缓解冷启动和超大 item 词表问题。

> 用户侧 Encoder 负责建模多尺度兴趣，包括用户静态画像、短期行为、高正反馈行为和长期历史兴趣。其中长期行为可以达到十万级视频，OneRec 通过层次化聚类和 QFormer 压缩成固定长度 token，避免简单截断导致长期兴趣丢失。Decoder 则像语言模型生成 token 一样，从 BOS 开始逐步生成单个目标视频的 coarse-to-fine 语义 ID，训练目标是 next-token prediction，本质上把“预测用户喜欢哪个视频”转化成语义 token 的序列生成问题。

> 预训练阶段主要学习传统曝光分布下的用户-视频匹配关系，但仅靠预训练会受传统推荐系统的样本分布限制，所以 OneRec 又引入了 Reward System 做偏好对齐。Reward 包括用户偏好 P-Score、格式 Reward 和工业目标 Reward。P-Score 用神经网络融合 CTR、观看时长、点赞、评论、关注等多目标，格式 Reward 解决 RL 后生成非法 semantic id 的问题，工业 Reward 则可以把生态、商业化、冷启动等平台目标统一纳入优化。策略优化上使用 ECPO，是对 GRPO 的稳定性改进，通过 early clipping 限制异常大的策略比率，同时用 RSFT 损失维持生成稳定。

> 我理解 OneRec 的关键价值有三点。第一，它把推荐从“候选生成+逐点打分”转成“端到端生成”，统一了召回和排序的目标。第二，它把 item 表示做成可组合的语义 token，既降低生成空间，又带来相似 item 之间的知识迁移。第三，它把多目标业务优化放到 Reward System 里，用类似大模型后训练的方式做偏好对齐，这也是推荐大模型区别于传统推荐模型的核心方向。

> 从线上结果看，OneRec 已经部署到快手和快手极速版的核心短视频场景，论文里提到覆盖约 25% 总 QPS。相比传统多阶段系统，OneRec 结合 Reward Model selection 后在 App Stay Time、Watch Time、互动指标上都有提升，这说明生成式推荐不只是学术范式变化，而是已经能在高 QPS、低延迟的工业系统里跑通。

**一句话总结：**
> OneRec 本质上是把短视频推荐系统大模型化：用语义 ID 作为推荐语言，用 Transformer 建模用户兴趣并自回归生成候选视频，再通过 Reward System 对齐用户偏好和平台目标。


讲讲强化学习怎么赋能LLM4Rec，你感觉生成式推荐到底能带来什么？
>强化学习赋能 LLM4Rec，我理解核心不是“换一个训练算法”，而是把推荐系统从监督学习里的“拟合历史曝光分布”，推进到“直接优化最终用户体验和业务目标”。

>传统推荐大多是 SFT/监督学习范式：用户看过什么、点过什么、停留多久，模型就学这个分布。但这里有两个问题。第一，训练数据来自旧推荐系统的曝光结果，本身带有系统偏差，模型容易被限制在旧系统的天花板里。第二，推荐目标不是单一的点击率，而是观看时长、互动、留存、内容生态、创作者公平性、商业化等多目标，单靠交叉熵或者 BCE 很难端到端表达。

>RL 的价值就在这里。对于 LLM4Rec 或生成式推荐，模型输出的是 item semantic id 或推荐序列，我们可以把生成结果送到 Reward System 里评分，再用 PPO/GRPO/ECPO 这类策略优化方法提高高 reward item 的生成概率。Reward 可以来自用户偏好模型，比如 P-Score，也可以来自真实用户反馈，比如播放时长、完播、点赞、关注，还可以加入工业目标，比如冷启动内容扶持、低质内容抑制、生态分发约束。这样推荐模型不只是模仿历史日志，而是在生成空间里主动探索更优推荐。

>但我觉得 RL 在推荐里也有难点。推荐不像数学题有明确对错，reward 设计很容易有偏，比如只优化观看时长可能鼓励标题党或低价值沉迷内容；只依赖 Reward Model 又可能 reward hacking。所以 OneRec 里会做 P-Score 多目标融合、Format Reward 保证 semantic id 合法、Specific Industrial Reward 控制生态目标，本质上都是在解决“什么是好推荐”这个问题。

>至于生成式推荐到底能带来什么，我觉得有三点。

>第一是统一架构。传统推荐是召回、粗排、精排、重排多阶段系统，每一层都有自己的目标和模型，容易出现目标不一致和信息损耗。生成式推荐把推荐建模成“给定用户上下文，生成 item semantic id”，可以把召回和排序往一个统一模型里收敛，更接近大模型范式。

>第二是更好的 item 表示和泛化。直接生成 video id 不现实，因为 item 空间太大，而且新视频不断出现。semantic id 把 item 表示成粗到细的 token，相似视频共享部分 token，模型可以在语义 token 空间里迁移知识。新视频只要能通过内容和协同信号编码成 semantic id，就有机会被推荐，这对冷启动和长尾分发有价值。

>第三是让推荐系统具备后训练能力。以前业务目标变了，可能要在召回、排序、重排各阶段加规则、调权重、补策略，系统越来越复杂。生成式推荐如果有统一的 Reward System，就可以像 LLM 后训练一样，通过 reward shaping 或 RL 对齐用户偏好和平台目标。这是我认为最重要的变化：推荐系统从“工程拼接的多阶段打分系统”，变成“可预训练、可扩展、可对齐的生成模型”。

>不过我不会说生成式推荐已经完全替代传统推荐。它真正的优势在于给推荐系统打开了 scaling 和 RL 对齐的空间，但工业落地还要解决生成合法性、低延迟高 QPS、reward hacking、在线反馈闭环和多目标稳定性这些问题。OneRec 的意义就在于它证明了这条路线不是只停留在论文里，而是可以在快手这种高流量场景中跑通。

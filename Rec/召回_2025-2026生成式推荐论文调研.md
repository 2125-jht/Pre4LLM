# 2025–2026 生成式推荐论文调研：面向三层 SID 召回与路径级 PRM

> 调研时间：2026-08-27  
> 面向项目：快手主站三层 Semantic ID 自回归召回、路径级 PRM、PRM-guided Beam Search 与线上推理优化  
> 筛选原则：只保留与当前技术范式能直接对话的工作；优先原论文与正式会议页面，2026 年尚未正式发表的工作明确标为预印本。

## 1. 先给结论

这批论文中，对当前项目最有价值的不是“换一个全新的生成范式”，而是沿现有链路补齐六个问题：

1. **SID 是否足够好**：固定离散 SID 存在量化目标与推荐目标不一致、编码冲突和热门前缀失衡问题；ETEGRec、DIGER、GRID、OneMall 分别给出端到端对齐、可微 SID、系统性经验和工业 Tokenizer 方案。
2. **PRM 应怎样监督每一步路径**：Flower 提供真正的前缀过程监督视角；RankGR 则把曝光、点击、购买等分级反馈引入 listwise preference learning，且候选 Query 对用户历史做 Cross-Attention 的结构与当前 PRM 非常接近。
3. **PRM 只剪枝是否浪费了分数信息**：RecoChain、COBRA、RankGR 都说明，生成分数之外再引入候选精细打分并做分数融合，可能比“PRM 只决定去留、最终仍按 Decoder 概率排序”更充分。
4. **长序列怎样低成本进入 Decoder/PRM**：OneMall 的 Query-Former 将多类长行为序列压缩成少量连续 token，再作为 Cross-Attention K/V，与当前下一步计划高度一致。
5. **512 路 Beam 怎样稳定上线**：xGR 专门研究生成式推荐服务，覆盖 Beam 分叉后的 KV Cache 共享、合法路径约束、提前终止排序和流水化执行，最适合对照当前推理链路。
6. **怎样把算力集中到真正生成 SID 的 Decoder 上**：OneRec-V2 的 Lazy Decoder-Only 与当前“轻量用户 Context Processor + Cross-Attention K/V + 三层 SID Decoder”几乎同路，并进一步通过去除 K/V 投影、跨层 KV 共享和 GQA 支持模型扩展。

建议精读顺序：**OneRec-V2 → RankGR → Flower → RecoChain → xGR → GRID → OneMall**。其余论文作为 SID、端到端对齐、开源复现和显式推理方向的补充。

## 4. 逐篇分析

### 4.1 OneRec-V2：与当前生成架构最接近的系列工作

**为什么必须补入**：OneRec-V2 直接针对 OneRec-V1 的两个瓶颈：长用户上下文的编码占据绝大多数计算，以及仅依赖 Reward Model 做偏好对齐会带来采样开销和 Reward Hacking。论文报告在 V1 的 512 长上下文配置下，Context Encoding 占总 FLOPs 的 97.66%，而真正生成目标 SID 的部分只占 2.34%。

**Lazy Decoder-Only 架构**：

- 用户画像、短期和长期行为由轻量 Context Processor 统一到相同维度，直接产出供 Cross-Attention 使用的 K/V；不再使用完整 Transformer Encoder，也不把历史 token 放进普通 Decoder 做全量 Self-Attention。
- Decoder 只处理 `[BOS, sid1, sid2]`，预测三层 SID；每层由 Lazy Cross-Attention、Causal Self-Attention 和 FFN/MoE 组成。
- Cross-Attention 去掉常规 K/V Projection；多个 Decoder Block 可共享一组上下文 K/V，还可令 `K=V`，并使用 GQA 减少 KV Head 数与内存访问。
- 论文报告相对传统架构总计算降低 94%、训练资源降低 90%，并扩展到 8B 参数。这里是论文自身配置下的结果，不能直接视为当前模型的预期收益。

**与当前项目的逐项对应**：

| OneRec-V2 | 当前项目 | 判断 |
|---|---|---|
| Context Processor 生成用户上下文 K/V | 静态特征和 200 条点击经 MLP + LayerNorm 后作为 K/V | 主体思路相同 |
| Lazy Decoder 只处理 BOS 与三层 SID | START 后自回归生成三层 SID | 基本相同 |
| 三层 SID | 三层 SID | 相同 |
| 跨层 KV 共享、K/V tying、GQA | 已有 Cross-Attention KV Cache，但未在文档中体现这些结构化共享 | 是最直接的新增优化点 |
| 线上 context≈3000、beam=512 | 行为序列最长 200、beam=512 | Beam 规模相同，V2 的长上下文优化更激进 |
| 真实用户反馈 RL | NTP + 路径 InfoNCE PRM | 当前更轻；V2 可指导消费反馈标签设计 |

**偏好对齐**：V2 不只让 Reward Model 给分，而是直接利用真实播放反馈。Duration-Aware Reward Shaping 先按视频时长做对数分桶，再计算用户在同类时长视频中的播放时长分位数，以削弱“视频越长、天然播放时长越高”的偏差；随后通过 Gradient-Bounded Policy Optimization 稳定正负样本更新。

**线上结果与风险**：论文以 1B 模型、约 3000 长上下文和 Beam-512 部署，在快手/快手极速版相对 V1 报告 App Stay Time +0.467%/+0.741%。但其关闭缓存的附录同时观察到冷启动视频播放下降和聚类密度上升，说明只优化消费反馈可能损伤生态指标；面试中应主动提到这项权衡。

**最值得复现的实验**：

1. 在当前 2 层 Decoder 上比较“每层独立 K/V Projection”与“Context Processor 直接产出 K/V、跨层共享”。
2. 分别消融 `K/V tying` 和 GQA，记录 Recall、PRM 保留率、Cross-Attention 耗时与 KV 显存。
3. 给 PRM 增加按视频时长归一化的消费标签，比较原始播放时长、播放完成率和用户内同 duration bucket 分位数。

### 4.2 RankGR：与当前 PRM 最接近的工作

**核心问题**：单纯 NTP 只会提高真实 SID 的生成概率，无法充分利用“购买 > 点击 > 曝光未点 > 伪曝光”等有序反馈，也缺少对 Beam 候选之间相对质量的直接学习。

**方法**：

- Initial Assessment 阶段在 NTP 基础上加入 Listwise DPO，使模型学习同一请求内不同反馈层级的候选顺序。
- Refined Scoring 阶段用候选 codeword 表示作 Query，对全部输入隐藏状态作 Cross-Attention，再由 MLP 输出细粒度相关性分数。
- 论文同时讨论候选预计算和流式训练，以降低 listwise 样本构建成本。

**与当前项目的关系**：它的候选 Query—用户上下文 K/V—MLP 打分结构，几乎就是当前路径级 PRM 的近邻方案；主要差异是 RankGR 使用分级 listwise 反馈并将打分用于更完整的候选排序，而当前 PRM 主要用 InfoNCE 学二元匹配，线上只剪枝。

**最值得复现的实验**：保持生成器不变，把 PRM loss 从单一 InfoNCE 扩展为“InfoNCE + 同请求分级 listwise loss”，负样本优先选择 Decoder 高分但消费较差、或共享同一 SID 前缀的难负样本。先做离线消融，不必直接上完整 DPO。

**注意**：该工作目前是 2026 年预印本，线上结果来自淘宝场景；应借鉴监督结构和候选打分方式，不直接外推收益幅度。

### 4.3 Flower：把完整路径奖励分解到每一步前缀

**核心问题**：只有完整 item 或完整序列上的奖励时，中间 token 缺少信用分配；这与当前项目希望用 PRM 抑制 SID 路径逐层语义漂移的动机一致。

**方法**：Flower 把合法 item 前缀组织成树，并用 GFlowNet 的状态流描述从根节点走到终止 item 的概率。终点 item 奖励会反向形成前缀状态流，相邻状态流之比成为逐 token 的过程奖励，从而在生成过程中就区分有前景和无前景的路径。

**与当前项目的关系**：

- 当前 PRM 的监督来自目标路径与 Batch 内负路径的对比；Flower 的监督显式要求“前缀价值与其所有可达终点奖励一致”。
- 对 SID 树而言，可将一个前缀下真实视频的观看时长、互动价值或排序模型分数聚合为前缀价值，作为 PRM 的蒸馏目标或辅助标签。

**最值得复现的实验**：按 SID Trie 离线聚合 `prefix → descendant reward`，比较 `max / mean / logsumexp` 三种前缀价值定义，再与现有 InfoNCE 联合训练 PRM。

**注意**：Flower 原始任务偏 LLM 生成物品文本/标识，不是完全相同的三层 SID 工业实现；可迁移的是“终点奖励如何变成前缀监督”，不是整套模型。

### 4.4 RecoChain：PRM 分数是否应该进入最终排序

**核心问题**：生成式召回与精排往往独立优化；仅按生成概率排序，不能充分利用候选与用户细粒度交互信息。

**方法**：RecoChain 使用共享 Decoder-only 主干先经 Beam Search 生成层次 SID；对每个候选检索相关历史行为，将候选和其相关历史追加到已有上下文，复用 Prefill KV Cache，再由排序头预测点击分数。最终将生成路径对数概率与排序概率进行融合。

**与当前项目的关系**：当前 PRM 已经计算了用户—路径匹配分数，却只让它参与 Top-1024→Top-512 的去留。RecoChain 提示至少应验证：保留路径最终按

`final_score = decoder_log_prob + α × prm_score`

排序，是否优于仅按 Decoder 累积概率排序。

**最值得复现的实验**：不改训练，先用离线网格搜索 α 做后融合；若有效，再训练一个以 PRM、Decoder 分数、SID 层级和基础统计特征为输入的小型 calibration/rank head。

**注意**：RecoChain 截至调研日仍是较新的预印本，结构复杂度和在线延迟需要独立评估。

### 4.5 xGR：围绕生成式推荐定制的在线服务

**核心问题**：通用 LLM serving 没有充分利用推荐 SID 树浅、Beam 宽、合法路径有限等特点，宽 Beam 下 KV Cache、排序和候选管理会成为瓶颈。

**方法要点**：

- 区分 Beam 分叉前共享和分叉后独立的 KV Cache，减少重复存储与拷贝。
- 将 Prefill、逐层 Decode、候选筛选拆成更适合生成式推荐的执行阶段。
- 使用合法路径 mask、数据结构复用和提前终止排序，避免对不可能保留的候选做完整工作。
- 通过多流流水化隐藏部分计算与传输开销。

论文最新版本报告在严格延迟约束下至少 **2.89×** 吞吐提升，并给出大规模线上部署经验；早期版本与最新版本的数字不同，本文采用 2026-06 的 v3 口径。

**与当前项目的关系**：它是 Decoder Self/Cross-Attention Cache、PRM KV Cache、512 Beam 扩展和显存开销最直接的系统对照。

**最值得复现的实验**：把每步耗时拆成 `Decoder / TopK / PRM / Gather-Reorder / KV Copy`，同时记录活跃 Beam 数和峰值显存；否则只看总耗时，很难判断下一轮优化应落在算子、缓存还是搜索策略。

### 4.6 GRID：最适合作为实验检查表的系统研究

**定位**：GRID 不是单一新模型，而是 Semantic ID 生成式推荐的统一实现与大规模消融研究，覆盖 Res-KMeans、RQ-VAE 等 Tokenizer，Encoder–Decoder / Decoder-only 架构，数据增强和带 KV Cache 的 Beam Search。

**对当前项目有价值的经验**：

- 在其测试条件下，简单的 Residual K-Means 有时不输甚至优于更复杂的 RQ-VAE，说明先做 SID 质量诊断比盲目换 Tokenizer 更重要。
- 更大的语义编码器未必带来同比例收益。
- 其对比中 `3 × 256` SID 配置效果较好，继续增加层数可能降低可学习性；这是经验结论，不应当作普适定律。
- Encoder–Decoder 在其标准对比中明显优于普通 Decoder-only；但当前项目是“用户特征经 MLP 后作为 Decoder Cross-Attention K/V”的混合结构，不能直接等同于论文里的纯 Decoder-only。
- 滑窗构造训练样本、去重和数据处理可能比复杂建模带来更稳定的收益；约束/非约束 Beam 的差异需要按数据集实测。

**最值得复现的实验**：建立 SID 召回固定基准，统一对比数据切片、SID 结构、模型结构和 Beam 设置，避免多个改动打包后无法归因。

### 4.7 OneMall：Q-Former 与当前下一步计划高度一致

**整体架构**：OneMall 使用业务对齐的多模态 Item Tokenizer、Query-Former 压缩多类行为序列、Cross-Attention 融合用户上下文、Decoder-style Sparse MoE 自回归生成三层 SID，并利用排序模型奖励做 DPO/GRPO。

**长序列部分尤其值得关注**：论文示例用约 10 个查询 token 压缩长度约 500 的单类行为序列，再将点击、曝光、购买等压缩结果共同作为 SID Decoder 的 Cross-Attention K/V。其组件实验中，Query-Former 将总序列长度从 1205 压到 160、计算量从 34.4 GFLOPs 降到 9.2 GFLOPs，而 HR@50/100/500 只分别下降约 0.5/0.3/0.4 个百分点。该结果来自快手电商，不保证主站短视频场景同幅度成立，但方向非常直接。

**与当前项目的关系**：

- 当前最长 200 条点击序列直接进入 Decoder 和 PRM 的 K/V；Q-Former 可同时降低两边 Cross-Attention 和 KV Cache 成本。
- OneMall 对点击、曝光、购买等行为分别压缩，提示未来扩行为类型时不必简单拼成长序列。
- 其 SID 冲突率、Exclusive Rate 和辅助对比学习指标，也可补充当前仅看召回效果的评估。

**最值得复现的实验**：比较 8/16/32 个 Q token，固定 Decoder/PRM 参数，画出 `完整路径 Recall—PRM 保留率—Leaf 耗时—KV 显存` 的 Pareto 曲线。

### 4.8 OneRec：快手生成式推荐的整体工业参照

**方法**：OneRec 以平衡残差聚类构造 SID，使用用户行为进行 Session-wise 列表生成，以稀疏 MoE 扩模型容量，并通过奖励模型、自难负样本和迭代 DPO 对齐推荐偏好。论文报告线上观看时长提升 1.6%。

**与当前项目的关系**：它说明 SID 自回归生成不必停留在召回命中目标，可以继续向列表级体验和排序奖励对齐；但当前项目更轻量，重点是路径级 PRM 和低开销召回，不宜一次性照搬列表生成与 RL 全链路。

**最值得借鉴的点**：利用当前 Decoder 高分但线上低消费的候选构造 self-hard negative；相比 Batch 内任意负样本，这类负样本更贴近 PRM 在 Beam 中真正需要解决的错误。

### 4.9 ETEGRec：让 Tokenizer 与推荐目标共同学习

**核心问题**：常见流程先通过内容重建或聚类训练 Item Tokenizer，再冻结 SID 训练推荐模型，两阶段目标不一致；语义上相近的物品不一定在用户偏好空间中相近。

**方法**：ETEGRec 联合优化 RQ-VAE Tokenizer 与生成推荐器，通过 Sequence–Item Alignment 和 Preference–Semantic Alignment 让行为序列表示、目标物品表示与离散语义表示互相对齐，并采用交替优化提高稳定性。

**与当前项目的关系**：如果当前三层 SID 的主要问题来自“同路径物品偏好不一致”或“目标物品经常落在热门冲突路径”，端到端对齐比继续堆 PRM 容量更接近根因。

**建议**：先做低成本审计——统计同 SID/同前缀物品的消费标签方差、碰撞率、覆盖率和热度分布；只有确认问题明显后，再评估端到端 Tokenizer，避免把系统复杂度提前引入线上链路。

### 4.10 DIGER：让 SID 可微但仍保持离散推理

**方法**：DIGER 前向使用硬离散 code，反向使用带 Gumbel 扰动的软分布传梯度；Gumbel 探索缓解 codebook collapse，并通过基于标准差和频次的不确定性衰减逐渐从探索转向稳定编码。

**与当前项目的关系**：它比 ETEGRec 更直接地解决“推荐损失无法回传到 SID”问题，同时仍保留离散 SID 及自回归推理形式，范式没有明显偏离。

**风险**：SID 在线稳定性、物品索引重建和新旧模型兼容是工业系统的关键约束。即使离线有效，也应先考虑周期性离线更新和版本化 SID，而不是实时改变线上 code。

### 4.11 COBRA：用稠密表示补足 SID 的粒度损失

**核心问题**：离散量化会丢失物品细粒度信息，同一 SID 或相邻 SID 下仍可能有较大的用户偏好差异。

**方法**：COBRA 先生成稀疏语义 ID，再以其为条件生成稠密向量；训练结合 SID 交叉熵和 Batch 内对比学习，推理时先 Beam Search 生成稀疏候选区域，再在区域内做 ANN，并通过 BeamFusion 融合生成分数与近邻分数。

**与当前项目的关系**：它提供了 PRM 之外的另一种“粗路径 + 细粒度”思路。当前 PRM 细化的是用户—路径匹配，COBRA 细化的是路径内物品表示；两者可以互补，尤其适合 SID 冲突较高或一条路径映射多个视频的情况。

**代价**：引入稠密向量生成和 ANN 会增加索引与服务复杂度。短期更现实的是先借鉴 BeamFusion 的分数融合思想，而不是整体替换现有 SID 索引。

### 4.12 OpenOneRec：最适合复现和建立外部基准的系列资源

**定位**：OpenOneRec 将 OneRec 从单一工业模型扩展为开源基础模型、数据集、Benchmark 和完整训练流水线。它发布 RecIF-Bench、层次化 Itemic Token、1.7B/8B OneRec-Foundation 模型，以及数据处理、混合预训练、SFT、on-policy distillation 和推荐 RL 代码。

**数据与任务**：RecIF-Bench 覆盖短视频、广告和商品三个域，约 1.2 亿次交互、20 万用户和 1534 万物品；同时包含长序列、多行为、多模态和跨域任务。论文另提供约 9600 万次交互的训练数据。其评测从 Item Understanding 延伸到视频/广告/商品 Next-Item Recommendation 和解释推理。

**与当前项目的关系**：

- 可用其中的预计算层次 item token 和短视频行为数据复现三层 SID 召回基线，减少仅凭公司内部代码讲面试时的不可验证部分。
- 可把当前 NTP、普通 Beam 与 PRM-guided Beam 做成一个小规模外部实验，验证“路径监督是否提高真实路径保留率”。
- 它的重点已向通用基础模型和跨域迁移移动，不应把 1.7B/8B LLM 路线当作当前轻量线上召回的直接替代方案。

**建议用途**：将它视为代码和 Benchmark 资源，而不是必须复刻的线上架构；如果准备面试，至少熟悉其 Itemic Token、RecIF-Bench 和 pre-training/post-training 分层。

### 4.13 OneRec-Think：OneRec 系列的显式推理扩展

**核心变化**：原始 OneRec 根据用户行为直接生成候选，是隐式偏好预测；OneRec-Think 试图让模型在文本空间中显式推理，再做个性化推荐。其三个模块是 Itemic Alignment、Reasoning Scaffolding，以及考虑推荐“多答案都可能有效”的专用奖励。

**工业部署**：论文使用 Think-Ahead 架构把较重的推理提前或解耦，以控制在线成本，并在快手报告 App Stay Time +0.159%。该工作已正式发表于 ACL 2026 Long Paper。

**与当前项目的关系**：直接迁移距离较远，因为当前目标是低延迟三层 SID 召回，并不生成自然语言 CoT；但“同一个用户存在多个有效下一物品”的 multi-validity 奖励，对 PRM 的 False Negative 问题很有启发。可借鉴的是多正例/软标签设计，不是在线生成长推理文本。

## 5. 对当前项目最值得做的实验

### P0：不改变主范式即可完成

1. **PRM 剪枝与排序作用拆分**  
   对比：仅剪枝；剪枝后按 `Decoder + α·PRM` 排序；独立轻量 rank head。重点观察完整路径 Recall、目标路径 PRM 保留率、Top-K 消费标签质量和增量候选占比。

2. **PRM 监督升级**  
   在现有 InfoNCE 上增加同请求 listwise/graded preference loss。优先使用高 Decoder 分低消费、同前缀 sibling、热门路径采样得到的难负样本；继续保留 False Negative Mask 与采样校正。消费标签可增加 OneRec-V2 式 duration bucket 用户内分位数，降低原始播放时长的时长偏差。

3. **逐层 Beam 生存分析**  
   分别记录真实 sid1、sid1-2、sid1-3 在 Decoder Top-1024 和 PRM Top-512 前后的存活率。这样可以区分问题来自 Decoder 漏召回，还是 PRM 误剪枝。

4. **服务链路画像**  
   拆分 Decoder、TopK、PRM、Beam gather/reorder、KV copy 的平均和 P99 耗时；记录共享/独立 KV 大小、实际合法分支数和无效路径率，再决定是否做 xGR 式缓存布局和提前终止。

### P1：需要新增模块，但与现有架构兼容

5. **OneRec-V2 式 Lazy Cross-Attention**  
   在当前用户 Context Processor 后直接产生 K/V，比较每层独立 K/V、跨 Decoder 层共享 K/V、`K=V` tying 与 GQA。Decoder 和 PRM 是否共享同一份用户 K/V 也应单独消融，并同时记录效果、延迟和峰值显存。

6. **Q-Former 压缩 200 条历史**  
   用 8/16/32 个查询 token 替代原始行为 K/V，让 Decoder 和 PRM 共享压缩结果；同时评估效果、Leaf 延迟和 KV 显存，避免只看 FLOPs。

7. **SID 健康度与 Tokenizer 对照**  
   建立每层 code 使用频率、熵、冲突率、Exclusive Rate、同路径标签方差和长尾覆盖率。先比较当前方案与 Res-KMeans/FSQ 等离线基线，再决定是否值得引入 ETEGRec/DIGER 式联合学习。

其中第 5、6 项是两条不同的长序列路线：Q-Former 先压缩 token 数；OneRec-V2 则保留长上下文，但避免对上下文做重型 Encoder 和重复 K/V 投影。当前只有 200 条历史，应先用真实算子耗时决定哪条路线更划算，也可以组合使用。

### 暂不建议优先做

- 直接将整个生成器改为扩散或并行集合生成：会同时改变训练、搜索和部署，难以与当前收益归因。
- 直接上线完整 DPO/GRPO：应先验证更轻量的分级 listwise loss 或排序模型蒸馏是否有效。
- 只扩大 Beam：如果真实路径在 Decoder Top-1024 内但被 PRM 错剪，扩大 Beam 只会放大计算量，不能解决监督问题。

## 6. 面试时可用的一段总结

> 2025–2026 年与我们最相关的生成式推荐工作主要沿五条线推进：第一是让 Semantic ID 从固定聚类走向推荐目标对齐甚至可微学习；第二是把最终物品价值分解成路径前缀监督，或利用曝光、点击、消费等分级反馈训练候选打分；第三是将生成概率和细粒度排序分数结合，而不只靠 Beam 的 token 概率；第四是针对宽 Beam、KV Cache 和长用户序列做工业服务优化；第五是像 OneRec-V2 一样，用 Lazy Decoder-Only 将算力集中到真正产生推荐决策的三层 SID 上。对我们当前方案来说，优先级最高的不是换掉三层 SID 自回归范式，而是验证 PRM 分数融合、listwise 难负样本、逐层真实路径存活率，以及 Lazy Cross-Attention 与 Q-Former 两条长序列优化路线。
